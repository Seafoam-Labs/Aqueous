# Co-installable Git core packages

For the complete desktop and login entries, use the optional
[`aqueous-desktop-git` or `aqueous-desktop-intel-git` meta packages](git-desktop-packages.md).
The core packages below remain available independently.

These packages install development compositor/helper tools alongside stable
Aqueous and the existing combined legacy packages. They do not replace packages,
claim stable package provisions, install session entries or enable shell services.

| Package | Commands | Private prefix | Config directory |
| --- | --- | --- | --- |
| `aqueous-core-git` | `aqueous-git`, `aqueousctl-git`, `aqueous-config-git` | `/usr/lib/aqueous-git` | `$XDG_CONFIG_HOME/aqueous-git` |
| `aqueous-core-intel-git` | `aqueous-intel-git`, `aqueousctl-intel-git`, `aqueous-config-intel-git` | `/usr/lib/aqueous-intel-git` | `$XDG_CONFIG_HOME/aqueous-intel-git` |

If XDG_CONFIG_HOME is unset, configuration is under `~/.config`. Each instance
has its own `wm.toml`, `outputs.toml`, `layout.toml`, `input.toml`, `rules.toml`,
`appearance.toml` and optional executable `init`. Configuration journals live
under `$XDG_STATE_HOME/<instance>/config-writer`, defaulting to
`~/.local/state/<instance>/config-writer`. IPC sockets use a private instance
subdirectory under XDG_RUNTIME_DIR. The standard build supports x86_64 and
aarch64; Intel retains a portable x86_64 baseline. Both variants can coexist.

The original `aqueous-git` and `aqueous-git-intel` **package names** refer to
previously published combined desktop packages; their recipes have been retired.
The `aqueous-git` **command** belongs to `aqueous-core-git`. Existing legacy
installations use the unsuffixed `aqueous` command and are not automatically
renamed or replaced.

## Building

Run `makepkg -si` from `packaging/arch/aqueous-core-git` or
`packaging/arch/aqueous-core-intel-git`. Each recipe fetches the current upstream
Git source and pinned wlroots archive. Publish the source changes before using
these recipes against upstream. Checks require a normal Arch build environment;
GTK, welcome, DMS and a portal backend are not built by these core recipes.

The shared build invokes Zig with `-Dinstance-name=aqueous-git` or
`-Dinstance-name=aqueous-intel-git` for both compositor and helper. Omitting this
option retains stable paths. Staging checks the metadata generated by both
builds and rejects the wrong instance or a test-only display-preview policy.
The private layout preserves the compositor's relative wlroots RPATH. Launchers
also put that instance's library and helper binaries first in the process's
search paths. No global linker configuration is changed.

## Running

Run `aqueous-git -c 'ghostty'` from a TTY or an appropriate nested compositor
environment to start a development instance. The Intel command is
`aqueous-intel-git`. Supply your own startup command or instance-specific `init`;
these packages do not start DMS or use the stable session initializer.

Inside a Git compositor's child environment, its suffixed helper/client keep the
current instance's Wayland and IPC endpoints. From a stable desktop, the helper
can inspect its private configuration offline:

```sh
aqueous-config-git snapshot --shell none
```

Git helpers default to `--shell none`; selecting a shell requires an explicit
option. The stable helper keeps its existing default.

To target an already running development compositor from another environment,
set its actual endpoints explicitly; do not guess `wayland-0`:

```sh
AQUEOUS_GIT_WAYLAND_DISPLAY=wayland-1 \
AQUEOUS_GIT_SOCKET="$XDG_RUNTIME_DIR/aqueous-git/ACTUAL_SESSION_ID/ipc.sock" \
  aqueousctl-git outputs --json
```

The values above are illustrative. Obtain both from the development compositor's
child environment. Wrappers discard inherited stable `AQUEOUS_*` source/socket
variables on entry from another instance. Explicit source overrides use
`AQUEOUS_GIT_CONFIG`, `AQUEOUS_GIT_LAYOUT`, `AQUEOUS_GIT_INPUT`,
`AQUEOUS_GIT_OUTPUTS`, `AQUEOUS_GIT_RULES` and `AQUEOUS_GIT_APPEARANCE`.
They are deliberate opt-ins and can point outside the private config directory.
The helper's generation, candidate validation and protected-apply rules remain
in force. The wrappers do not edit TOML.

Protocols are available through `aqueous-git-protocols.pc` or
`aqueous-intel-git-protocols.pc`, with separate XML directories. Wayland protocol
interface names stay unchanged because they are scoped to each display.

## Verification

`bash packaging/tests/test-git-packages.sh` checks both package layouts against
stable ownership, private command/library routing, config environment isolation
and rejection of wrong build metadata. Passing compositor/helper install trees
and a channel additionally checks real binary staging, library RPATH and helper
configuration/journal isolation:

```sh
bash packaging/tests/test-git-packages.sh /path/to/compositor-dist /path/to/helper-dist git
```

These checks do not constitute physical display acceptance or a migration of the
legacy desktop packages. The stable session/welcome/portal packages remain the
installed desktop integration until explicitly changed by the user.

## Switching the desktop shell

Inside a complete Git desktop session, run
`aqueousctl-git shell switch pearl|dms|noctalia` (choose one shell), or use
`aqueousctl-intel-git` for Intel Git. This requires the matching welcome worker
and the selected shell preset. The switch takes effect immediately and persists
across logins. Every shell's existing configuration is preserved. See the
[command reference](aqueousctl-command-reference.md#switch-desktop-shells-git-sessions-only)
for prerequisites, JSON output, and failure recovery.
